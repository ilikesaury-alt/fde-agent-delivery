## 1. 功能概述

**一句话**：贴一条文章链接或粘贴一段素材，一键生成一篇小红书风格图文笔记（主标题 + 2 个备选标题 + 正文 + 话题标签），生成结果自动存入历史，可回看、可重新生成一版。

- **面向谁**：个人自媒体创作者自用（单用户，用访问令牌保护）。
- **当前状态**：**已上线且全量 E2E 通过**（线上真 D1 + 真上游流式，T1–T16 全过，证据见 `product2/docs/e2e-evidence/live/README.md`）。
- **本版本包含**：
  - 链接抓取（自动提取网页正文）
  - 粘贴文本（抓取失败时的等效替代入口）
  - 超长素材自动压缩（约 6000 字以上）
  - 步骤级进度 + 正文逐字流式输出
  - 历史记录：列表 / 回看 / 删除 / 重新生成
  - 各字段独立复制（标题 / 正文 / 标签 / 整篇）
- **本版本不包含**：其他平台文案（公众号/抖音/微博）、自动发布到小红书、AI 配图、账号体系、批量任务。

## 2. 使用说明

### 入口
- 线上：https://content-studio.ilikesaury.workers.dev
- 工作台页面：`/`（首页，左侧输入、右侧成品、底部历史）

### 操作步骤
1. （若已配置访问令牌）在右上角「访问令牌」输入框填写令牌，会记住到浏览器本地。
2. 左侧选择输入方式：
   - **贴链接**：在输入框填入 `https://…` 文章链接，回车或点「生成笔记」。
   - **粘贴文本**：切到「粘贴文本」页签，把正文粘进文本框。
3. 点「生成笔记」。左侧下方出现三步行进度：
   | 步骤 | 含义 | 可能出现的情况 |
   |---|---|---|
   | 抓取正文 | 拉取链接正文 | 仅链接模式；文本模式显示「使用粘贴文本」跳过 |
   | 素材准备 | 超长素材压缩要点 | 素材 ≤6000 字显示「素材长度无需压缩」跳过 |
   | 生成笔记 | 调模型生成 | 显示「进行中…」直到首个字到达 |
4. 右侧成品区：正文**逐字**出现（带光标），生成完成后切换为分块卡片：
   - **主标题**（可复制；点击「备选标题 N 个」展开后可点击任一切换为主标题）
   - **正文**（显示字数，可复制）
   - **话题标签**（# 形式展示，可复制标签、可复制整篇）
5. 底部「历史记录」自动刷新，倒序展示每一次生成。

### 字段/按钮含义
| 元素 | 含义 |
|---|---|
| 生成笔记 | 开始一次流水线（抓取 → 准备 → 生成） |
| 换一版 | 用**同一次**素材再跑一次，开头钩子/标题角度会换（结果为新记录） |
| 复制标题 / 正文 / 标签 / 整篇 | 分别复制对应内容，成功后按钮短暂变「已复制」 |
| 备选标题 | 展开后可点击切换主标题，复制整篇时按当前主标题输出 |
| 历史 · 复制 | 直接复制该条笔记整篇 |
| 历史 · 重新生成 | 用该条记录的**原素材**重跑，产生新记录（旧记录保留） |
| 历史 · 删除 | 删除该条记录（不可恢复） |
| 历史 · 载入到工作台 | 把该条笔记载入右侧成品区查看/复制 |

## 3. 权限 / 配置变更

| 项 | 说明 | 需要谁做 |
|---|---|---|
| `MAGPIE_BASE_URL` / `MAGPIE_API_KEY` | 上游模型网关地址与密钥。**未配置时生成接口返回明确错误**，历史接口不受影响 | 部署/运维 |
| `MAGPIE_MODEL` | 模型名，默认 `deepseek-chat`。**延迟差异极大**（实测首 token 1.8s ~ 22.9s，个别模型 90s 无输出），建议选快模型 | 部署/运维 |
| `ACCESS_TOKEN` | 可选。设置后 `/api/generate`、`/api/jobs` 都要求 `Authorization: Bearer <token>`。**留空则不校验** | 部署/运维 |
| D1 数据库 `DB` | 历史记录存储。首次部署自动创建并应用 `db/migrations` | 部署/运维（见部署要点） |

**权限点**：无角色体系；单令牌全权限（可生成、可看历史、可删除）。

## 5. 已知问题与注意事项

| 项 | 说明 | 对业务的影响 |
|---|---|---|
| 动态渲染页抓不到 | Workers 无浏览器内核，微信/登录墙/强反爬/SPA 页面常抓不到正文 | 会明确报错并引导改用「粘贴文本」；**这是设计边界，不是 bug** |
| 模型延迟差异极大 | 实测首 token 1.8s ~ 22.9s；个别模型 90s 无输出 | 长等待时用户只能看到步骤进度；建议部署时选快模型 |
| 个别模型不吐正文 | 有模型只回流式空帧（推理字段） | 已兜底为「AI 返回结果为空，请重试。」，不会出现「成功但空白」 |
| 正文长度会波动 | prompt 要求 300–600 字，实际可能超出 | 允许 ±15%；若长期超限需调 prompt |
| 抓取不带重试 | 单次 10s 超时，失败即报错 | 网络抖动时用户需手动重试；换取更快失败反馈 |
| 历史记录存原文全文 | `sourceText` 落库用于「重新生成」 | 单用户自用可接受；若将来多人使用需评估隐私与存储上限 |
| 本地历史不持久 | 本地 shim 用进程内 SQLite | 本地重启即清空；线上 D1 持久 |
| 单平台 | 仅小红书 | 其他平台需后续版本 |

## 6. 部署与回滚要点（运维向）

> **当前部署记录**：2026-10-27 已上线（version `2ea32819`，D1 `content-studio-db` 已建库并应用 migration）。完整链路见 `product2/docs/deploy-content-studio.md`。

### 首次部署
1. `cd product2 && node node_modules/vite/bin/vite.js build`
2. 首次需建 D1：`npx wrangler d1 create <name>` + `npx wrangler d1 execute <name> --remote --file=db/migrations/0001_init.sql`（D1 id 写回 `void.config.ts` 的 `cloudflare.d1_databases`——**权威源只能是 void.config.ts**，`.void-wrangler.jsonc` 是生成物手改无效）
3. 部署：`npm run deploy -- --secrets .secrets.json`（脚本 `product2/scripts/deploy.mjs` = 构建 → `cd dist/ssr && npx wrangler deploy --secrets-file` → 线上双探针。**wrangler 直连**；`void deploy` 需要 `CLOUDFLARE_API_TOKEN`。脚本强制带 `--secrets-file` 且不带会清空 secrets；不要改用其他旧写法——产品①曾因此跳过静态资产上传导致全站 1101）
4. 首次部署必须带 secrets（`MAGPIE_BASE_URL` / `MAGPIE_API_KEY` / 可选 `ACCESS_TOKEN`）
4. **部署后必查**（产品① 1101 事故铁律）：
   - `wrangler versions view <version-id> --name <worker>`：必须同时看到 `env.ASSETS  Assets` 与 `env.DB  D1 Database`
   - 部署日志中 `assetUploadFileCount > 0`
   - 访问 `/api/health` 返回 `{"ok":true}`；页面不含 `Error 1101`

### 数据库
- D1：`content-studio-db`（`b3955476-b504-4b67-8fe8-b1e9cf35cc75`），migration 已应用 ✅
- 迁移目录：`db/migrations`（Void 约定）
- 回滚注意：**回滚 Worker 版本不会回滚 D1 数据**；涉及表结构变更的回滚需另行评估

### 回滚
```bash
wrangler deployments list --name <worker>
wrangler rollback <完整 version-id> --name <worker> --message "原因" -y
```
（必须用完整 version ID；回滚前确认目标是「最近的已知好版本」而非「当天第一个版本」——产品①踩过）

### 排查开关
- 服务端日志始终打一行上游状态（`[llm] upstream <status>: …`），用 `wrangler tail` / Dashboard logs 查看；**不会**透到前端
