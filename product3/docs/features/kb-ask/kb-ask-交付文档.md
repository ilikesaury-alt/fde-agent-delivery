# kb-ask 知识库问答 · 交付文档

> **受众**：测试同学 / 业务方。本文档不含实现细节；技术原理见 [kb-ask-工作原理.md](./kb-ask-工作原理.md)，技术交接见 [HANDOFF](../../HANDOFF-kb-ask.md)。
> **对应 revision**：线上版本 `74ca217b`（2026-10-28，线上接口 E2E 13/13 通过）。
> **交叉引用**：需求与验收标准见 [CONTEXT](../../../CONTEXT.md) §5；验收证据见 §9。

---

## 1. 功能概述

把**你自己的文档**变成一个可以提问的知识库：导入文档后，用自然语言提问，系统先在你的文档里检索依据，再基于依据生成回答，并**逐条给出引用**（文档名 + 位置 + 原文片段）。如果知识库里没有足够依据，系统会**明确说「未找到依据」并列出最接近的内容**，而不是编一个答案。

- **面向谁**：需要频繁查阅一批私有文档的人（内部手册、规范、项目文档）；单用户自用为主。
- **本版本包含**：4 种导入方式（粘贴 / .md·.txt 上传 / PDF 文本抽取 / 网页链接）、自动切分与索引、单轮问答、引用溯源、阈值拒答、文档删除、问答历史回看、访问令牌保护、离线评测脚本。
- **本版本不包含**（二期）：多轮追问、多知识库/多租户、权限分级（RBAC）、扫描件 PDF 的 OCR、检索结果重排（rerank）、关键词混合检索、用量与成本看板、用户反馈闭环。

## 2. 使用说明

打开页面后是左右两栏：**左侧管理知识库**，**右侧提问**。

### 2.1 导入文档（左侧）

页面顶部有三个页签，选择导入方式：

| 页签 | 用法 | 说明 |
|---|---|---|
| **粘贴文本** | 把内容粘进文本框 → 点「导入并索引」 | 支持 Markdown；`#` 标题会被识别为引用位置（如「部署手册 / 3. 回滚」） |
| **上传文件** | 选择 .md / .txt / .pdf | .md/.txt 直接读取；**PDF 在浏览器内抽取文字**，抽取完再点「导入并索引」 |
| **网页链接** | 粘贴 http/https 公网地址 → 导入 | 只支持公网地址；需登录/强反爬/纯前端渲染的页面抓不到正文，会提示改用粘贴 |

点击「导入并索引」后：

- 成功：提示「已导入：切分为 N 个片段。向量索引写入是异步的，约 1 分钟后才能检索到」，并显示 **60 秒倒计时**；文档出现在下方列表，状态「已就绪」。
- 拒答时若库内有 90 秒内刚导入的文档，会额外提示「索引写入是异步的，请等一会儿再问」。
- 内容已在库中：提示「该文档内容已在库中，已跳过重复导入」，不重复占用额度。
- 同来源（同一链接/同名文件）内容有变化：**自动整篇替换**（旧版本先保留，新版本成功后才删除）。

文档列表每行显示：名称、来源、状态（待处理/索引中/已就绪/失败）、片段数；失败时同行显示原因。右侧「删除」按钮会**同时删除该文档的索引向量**。

### 2.2 提问（右侧）

在问题框输入问题 → 点「提问」。回答过程有三段可见进度：**问题向量化 → 检索知识库 → 生成回答**，回答文字逐字出现；期间可点「取消」中止。

回答下方「引用来源」区逐条列出：

```
[1] 部署手册 · 3. 回滚
回滚使用带完整版本号的回滚命令，不要用简写。回滚前必须确认目标是「最近的已知可用版本」…
```

- 编号 `[1][2]` 与回答正文里的标注对应。
- 只列出**模型真正引用到**的片段；模型编造的编号会被丢弃，不会出现假引用。

**依据不足时**：显示「知识库中未找到足以回答该问题的依据。」，并列出「最相近的内容（可能是问法不同，或该内容尚未导入）」，每条带相似度分数。

### 2.3 访问令牌（右上角）

若部署时配置了访问令牌，需要在右上角填入，否则所有操作会提示「需要访问令牌」。令牌保存在浏览器本地，刷新不丢。

### 2.4 问答历史

`GET /api/history` 保留最近 50 条问答（含拒答记录）。**当前界面只提供接口，内置页面暂未展示历史列表**（二期补 UI）。

## 3. 权限 / 配置变更

| 配置项 | 作用 | 必填 | 谁来配 |
|---|---|---|---|
| `MAGPIE_BASE_URL` / `MAGPIE_API_KEY` / `MAGPIE_MODEL` | 生成回答所用的上游模型 | 是 | 运维（Worker secret） |
| `ACCESS_TOKEN` | 页面操作所需的访问令牌 | **强烈建议配** | 运维。⚠️ 不配置时接口对公网**完全开放**（含文档全文列表与删除），部署脚本会对缺失给出警告 |
| `RETRIEVE_TOP_K` | 检索取多少条片段（默认 6） | 否 | 运维（可调） |
| `RETRIEVE_MIN_SCORE` | 相似度阈值，低于即判为「无依据」（基线 0.35） | 否 | **需按线上真模型标定**，见 §6 |

数据库与向量索引在首次部署时创建（见 §6），不需要业务方操作。

| # | 用例 | 步骤 | 预期 |

| M10 | 取消 | 提问后立刻点「取消」 | 回答停止；按钮回到「提问」可用状态 |
| M11 | 删除连带清理 | 删除某文档后再问它独有的内容 | 该内容不再被引用；列表不再出现该文档 |
| M12 | 令牌保护 | 配置 `ACCESS_TOKEN` 后清空页面令牌再操作 | 提示需要访问令牌，接口返回 401 |
| M13 | 超限提示 | 导入一份明显超长文档 | 友好提示过长/片段过多，且列表**不出现**半成品文档 |

## 5. 已知问题与注意事项

| 项 | 说明 | 对业务的影响 |
|---|---|---|
| **扫描件 PDF 抽不出文字** | PDF 在浏览器内抽文本，图片型 PDF 无文字层 | 会明确提示需先 OCR；**这是设计边界，不是 bug** |
| **动态渲染页抓不到正文** | Worker 无浏览器内核，需登录/强反爬/SPA 页面抓不到 | 明确报错并引导改用「粘贴文本」 |
| **导入后数十秒内检索不到（重要）** | 向量库（Vectorize）的写入是**异步**的：接口返回「已就绪」只代表平台已接受写入，实际可检索实测需 **10–50 秒** | 导入后**立刻**提问该文档内容，会得到「未找到依据」——预期行为，不是导入失败。页面有 60 秒倒计时，拒答时也会提示「索引异步」。测试请等约 1 分钟再问 |
| **检索阈值已按真模型标定** | 默认 0.45（真 bge-m3 相关文本实测 0.52–0.74） | 已标定一次；上量后应按 §6 重跑评测扫曲线 |
| **单轮问答** | 不支持追问（如「那它的配额呢？」） | 需一次把问题问完整；多轮在二期 |
| **单知识库** | 所有文档在同一索引里 | 不同项目混在一起会影响检索精度；二期支持多库 |
| **嵌入有每日免费额度** | Workers AI 免费额度 10k Neurons/天 | 打满后导入会提示「今日嵌入额度已用尽，明日恢复」；问答也依赖嵌入，同样受限 |
| **问答历史暂无界面** | 接口有数据，页面未展示 | 二期补 UI |
| **引用片段是截断的** | 引用块展示约 240 字 | 需要看全文时去原文查；位置路径可帮助定位 |
| **同名/同链接文件视为同一文档** | 上传同名文件且内容不同 → 整篇替换 | 是预期行为；旧版本删除后不可恢复 |

## 6. 部署与回滚要点（运维向）

> **首次部署必须先建两个资源**，否则接口会报绑定缺失：
> ```bash
> npx wrangler d1 create kb-ask-db
> npx wrangler vectorize create kb-ask --dimensions 1024 --metric cosine
> ```
> 数据库 id 回填 `void.config.ts` 的 `cloudflare.d1_databases`（**唯一权威源**，不要手改 `.void-wrangler.jsonc`）。
>
> **migration 顺序不可换**（0002 依赖 0001 的表）：
>
> ```bash
> npx wrangler d1 execute kb-ask-db --remote --file=db/migrations/0001_init.sql
> npx wrangler d1 execute kb-ask-db --remote --file=db/migrations/0002_unique_content_hash.sql
> npx wrangler d1 execute kb-ask-db --remote --file=db/migrations/0003_indexed_at.sql
> ```
>
> 漏跑 0003 会导致导入报「no column named indexed_at」。

### 部署

```bash
cd product3
npm run deploy -- --secrets .secrets.json
```

脚本做三件事：构建 → `wrangler deploy --secrets-file` → 线上双探针（`/api/health` + 首页）。**必须带 `--secrets-file`，否则重部署会清空线上 secrets。**

### 部署后必查（四个绑定，缺一不可）

```bash
npx wrangler versions view <version-id>
```

| 核验项 | 期望 |
|---|---|
| `env.ASSETS` | 静态资产绑定存在，且部署日志 `assetUploadFileCount > 0` |
| `env.DB` | D1 绑定存在 |
| **`env.AI`** | Workers AI 绑定存在（否则导入/问答直接失败） |
| **`env.VEC`** | Vectorize 绑定存在，`index_name = kb-ask` |
| `/api/health` | 返回 `{"ok":true,"service":"kb-ask"}` |
| 首页 | 200 且非 `Error 1101` 错误页 |
| 线上接口 E2E | `ego-browser nodejs < e2e/live-e2e.mjs` → **13/13 通过** |
| 线上可达性探针 | `ego-browser nodejs < e2e/live-probe.mjs` → 首页/health/401 全过 |

> 线上验证**必须用 ego-browser 这类独立浏览器进程**发起：本机 Node/curl 对 `*.workers.dev` 可能超时（实测），会误判成服务故障。

### 阈值标定（上线后必做一次）

```bash
BASE_URL=https://<线上地址> ACCESS_TOKEN=<令牌> npm run eval
```

看四项指标：`Recall@k`、`拒答正确率`、`误拒率`、`引用准确率`。调 `RETRIEVE_MIN_SCORE`（Worker secret/var）重复跑，取「Recall 与误拒率平衡最好」的值写死。评测集会往知识库写入 4 篇示例文档，跑完可按需删除。

### 回滚

```bash
npx wrangler deployments list --name kb-ask
npx wrangler rollback <完整 version-id> --name kb-ask --message "原因" -y
```

⚠️ **回滚 Worker 不会回滚 D1 数据与 Vectorize 索引**。若新版本改过表结构或索引维度，需单独评估数据兼容性（维度不一致会导致检索报错）。

## 7. 二期新增功能（v2）

| 能力 | 入口 | 行为 |

| 混合检索 | 无 UI 开关（`HYBRID_ENABLED`） | 向量召回 + 关键词（中文双字 bigram + 英文/数字词，D1 倒排 + BM25）融合；错误码/型号这类词不再「搜不到」；检索步骤 chips 的 detail 会显示「向量 N 段 / 关键词 M 段」 |
| 扫描件 OCR | 左栏「上传文件」→ 扫描件分支 | PDF 抽不出文字时给出「OCR 识别（最多 5 页）」按钮：前端把页面渲染成 JPEG，逐页调 `/api/ocr` 交给 Workers AI 视觉模型；识别文本回填到**可编辑文本框**，由人校对后再导入（不自动入库） |
| 索引延迟提示 | 左栏文档行 + 拒答提示 | 文档行徽标区分「索引中 · 约 N 秒 / 已就绪（未验证）/ 可检索已验证」；每篇文档有「检测」按钮，真实检索一次确认向量是否可见；拒答时若库内 90 秒内有新导入，给出「索引写入是异步的」提示 |

### 7.1 使用说明（新增部分）

1. **多轮追问**：先正常提一个问题，得到回答后直接输入「它呢」「这个怎么配」这类短问；回答区上方的问句会显示改写后的检索查询，便于核对系统拿什么去搜。
2. **回看历史**：左侧会话栏点任一历史会话即可加载该会话全部轮次；点「+ 新会话」后输入框为空、消息流清空，旧会话仍留在列表里。
3. **扫描件**：选择 PDF 后若提示「未抽取到文字（可能是扫描件）」，点「OCR 识别（最多 5 页）」；识别完成后务必检查/修正文本框内容再点导入。**超过 5 页的扫描件只处理前 5 页**，其余页需转成文本后粘贴。
4. **索引延迟**：导入成功后列表徽标显示「索引中 · 约 N 秒」。想确认能不能搜，点该行的「检测」：得到「该文档的向量已可检索」即可正常提问；若提示「暂时还检索不到」，等 30–60 秒再点一次。

3. **会话无用户隔离**：仍是单用户令牌（与一期同口径），知道令牌就能看到全部会话。
4. **OCR / 探针会消耗 Workers AI 配额，且当前没有按用户配额计数**：`/api/ocr`（每页一次视觉推理）与 `/api/probe`（每次 1 次嵌入 + 1 次查询）都可用脚本重复调用。单用户令牌模型下不引入计数机制，**上线前必须配置 `ACCESS_TOKEN`**（未配置即对公网开放）。

6. **假 LLM 只引用 `[1]`**：本地评测的「引用准确率」因此对排序敏感；线上真模型会按内容选择性引用，指标口径以线上为准（阈值与指标仍需线上标定，沿用一期 D16 的未完成项）。
