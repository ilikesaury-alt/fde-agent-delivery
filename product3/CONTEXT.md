## 2. 候选清单

评分维度：**FDE 叙事强度**（能否讲清"我在交付而不是在玩 demo"）、**新技术含量**、**复用度**、**演示直观度**、**工作量**、**风险**。

### A. 交付验收机器人（acceptance-bot）★ 推荐

输入一条线上 URL + 一份验收清单（YAML/Markdown 勾选项）→ 用 **Browser Run 真浏览器**执行步骤（打开、点击、填表、断言文案）→ 产出**证据包**（每步截图 + 断言结果 + 耗时 + 失败定位 + Markdown 报告）。

- **FDE 叙事**：★★★★★ 这就是 FDE 每天在做的事——"交付不是我说好了，而是有证据"。与两产品的 E2E 实践、`product1/docs/e2e-evidence/` 方法论完全同源。
- **新技术**：Browser Run（真实浏览器）+ 异步任务（Queues）+ 报告产物（R2/静态）
- **复用**：Void 结构、令牌保护、错误收敛、部署脚本、CI、Node shim 模式
- **演示**：输入 URL+清单 → 90 秒后出报告（截图墙 + 红绿断言），面试官可当场给个自己的站点测
- **工作量**：中（4–6 天量级）
- **风险**：① 免费配额 10 分钟/天 → 缓解：手动触发 + 单次上限 + 步骤数上限；② 步骤 DSL 越做越大 → 缓解：MVP 只支持 5 个动作（goto/click/fill/expectText/expectVisible）+ 截图；③ 只能在 Worker 内跑 Browser Run（不能本地跑）→ 缓解：结果全落库，本地只测纯函数（DSL 解析/断言求值/报告渲染）

**通用性（适用其他项目吗）——能，被测对象是输入而非写死**：

```
输入：任意公网 URL + 声明式验收清单（YAML）
执行：Browser Run 真浏览器跑 goto/click/fill/expectText/expectVisible
输出：证据包（截图 + 断言 + 报告），按「项目标签」落库分组
```

执行器不知道也不关心被测项目是什么栈（React/Vue/Next/静态页/他人产品均可）；产品①② 只是第一批用户。适用：作品集回归、客户交付验收（给客户清单 URL 自触发拿证据报告）、任意公网 Web 上线冒烟。

**边界（诚实清单）**：
1. 登录墙：`fill` 可填表单，但**凭据注入是设计难点**（客户密码不能明文进 D1/env）——二期做「凭据按次传入不落库」
2. 内网/localhost/未公开 staging：Workers 够不到私有网络（除非 Cloudflare Tunnel），只测公网可达 URL
3. 非 Web 目标：纯 API/移动 App/桌面不在范围（`expectApi` 可作二期扩展动作）
4. 配额定位：免费 10 分钟/天 ≈ 10–20 步的**冒烟级**清单；不替代 Playwright 本地全量 E2E（互补：全量在 CI，线上冒烟+验收证据在产品③）
5. 像素级视觉回归：截图只作证据，不做 diff
6. 强反爬/风控站点：可能识别并拦截数据中心浏览器（Browser Run 的 UA/IP 段）

**叙事升级**：产品③ 从「作品集第三个 demo」变为「给 FDE/交付团队的通用验收工具，自己的两个产品是它的第一批客户」——对应调研看板里「面向 FDE 团队的协作工具」类高价值定位。

### B. 交付规格生成器（spec-forge）

粘贴客户访谈记录 / 需求文档 → **多轮追问**（缺什么问什么）→ 输出验收标准 + 边界 + 风险 + 工作量拆解 + 可直接交接的 Markdown 包。

- **FDE 叙事**：★★★★★（面试官就是客户："你给我做个需求澄清"）
- **新技术**：多轮会话状态（D1）+ 缺口检测 + 结构化输出校验（可加"覆盖率评分"）
- **复用**：产品① prompt/校验/注入防护、产品② D1 与会话
- **演示**：强（对话式，现场问答）
- **工作量**：小–中（2–3 天）
- **风险**：技术含量最低（本质 Prompt 工程 + 状态），容易被看成"又一个聊天框"；若无评分/覆盖率/缺口检测等硬机制，简历信号弱

### C. 企业知识库问答（kb 问答，RAG）★ 已拍板（2026-10-28）

> 对齐调研文档「进阶产品 3：行业 RAG / 情报平台」；模仿对象：`research/zhiyu-enterprise-kb`（企业知识中台，RAG 检索→权限过滤→引用溯源 + 幻觉治理三层防线，架构深度最高的参考仓）。**业务独立**：语料/演示不依赖产品①②，仅共享平台层。

多源（URL / Markdown / 纯文本）→ 切分 + 嵌入 Vectorize → 检索 + **引用溯源** + 无答案拒答 + 检索评测集（Recall@k / 拒答率）。

- **FDE 叙事**：★★★★（企业落地最常见场景）
- **新技术**：RAG 全链路 + 向量检索 + 评测集（这是作品集里最能证明"我懂质量"的部分）
- **复用**：产品② 抓取与文本处理
- **演示**：中（问答本身直观，但"引用对不对"要内行才看得出价值）
- **工作量**：大（6–10 天：PDF/中文切分、嵌入配额、评测集构造）
- **风险**：① PDF 解析在 Worker 内存/CPU 限制下麻烦；② 中文切分质量决定一切；③ 检索效果不达标会变成"看起来很唬人但不好用"

### D. 多 Agent 交付流水线（agent-runtime）

把「需求 → 方案 → 实现清单 → 验收」做成可恢复长任务：Queues 拆步 + D1 状态机 + **人工审批节点** + 全链路审计日志。

- **FDE 叙事**：★★★（基础设施视角，业务方难共鸣）
- **新技术**：★★★★★（编排、状态机、重试、审批、审计——但**不能用 Workflows/DO**，需自建，复杂度陡增）
- **工作量**：大（8–12 天）
- **风险**：高。Queues consumer 的 CPU/时长边界 + 自建状态机的幂等性，容易做成"能跑但脆"的系统；演示弱

### E. 定时情报雷达（cron-radar）

每天 Cron 抓 N 个源（RSS/网页）→ 变更检测 + 摘要 → 生成日报页 + 邮件推送（`send_email` 绑定）。

- **FDE 叙事**：★★★☆
- **新技术**：Cron + 增量状态（去重/变更检测）+ 邮件交付 + 成本控制
- **风险**：与产品①「日报」概念重叠，容易被读成"产品① 加个定时器"；演示需要等一天

## 5. 验收标准（第 2 步收敛后写死，2026-10-28）

> 候选 A 的验收草案已随选题落选归档（见 git `749367b`）。

1. **语料导入**：粘贴 / 上传 .md/.txt / URL 导入 / **PDF（前端 pdf.js 抽文本）** 四种方式均可创建文档；创建后自动切分 + `bge-m3` 嵌入 + Vectorize 入库
2. **增量导入幂等**：同一文档（按内容哈希）重复导入不产生重复向量；持续追加语料无副作用
3. **文档管理**：列表（名称 / chunk 数 / 状态 / 导入时间）、删除（连带清理对应向量）
4. **问答**：输入问题 → 检索 → magpie 生成（grounded 约束：只依据检索片段作答，引用标注 `[1][2]`）→ 返回「回答 + 引用块（文档名 + 原文段落 + 锚点）」，引用内容真实存在于库中（可核验）
5. **拒答**：检索无命中 / 低于相似度阈值时，明确返回「知识库中未找到依据」并列出最相近片段（不臆造）
6. **评测**：评测集 ≥15 个问答对（从导入语料人工出题）+ `npm run eval` 产出 Recall@k / 拒答正确率 / 引用准确率，结果可复现、可归档进 `product3/docs/e2e-evidence/`
7. **配额守卫**：单文档大小上限、单库 chunk 数上限；超限友好报错且不产生半成品文档
8. **令牌与密钥**：无令牌不可入库/问答/删除（401 契约与产品② 一致）；Workers AI / magpie 凭据仅存 Worker env，前端零密钥；未配置/无效凭据返回明确错误（502 文案约定同产品①②）
9. **历史问答**：问答记录落 D1，可回看
10. **本地可测性与部署绑定**：Vectorize 在 shim 中不可用 → repository 接口本地用内存余弦实现，同一套单测两边跑；`/api/ask` 为 SSE 流式（step/token/done 协议同产品②）；部署后 `versions view` 必含 `AI` / `VEC` / `DB` 三个绑定（防 1101 家族事故）

### 落选候选清单（库/依赖级）
| 候选 | 筛掉原因 | 复活条件 |
|---|---|---|
| Durable Objects / Workflows | Void 1.2.1 config 不支持，自建状态机风险>收益 | 出现真正需要跨请求状态机/长事务时 |
| Queues 异步导入 | 单文档批量嵌入同步可控，Queues 引入双实现成本 | 单文档 chunk 数超数百、同步请求预算真不够时 |

| 通用平台抽象 / 多知识库命名空间 | 奥卡姆，MVP 单库 | 出现多租户/多库需求时 |

### 技术选型
- **框架**：Void（vite build / routes/api/ 文件即路由 / defineHandler），与产品①② 同版本（void ^1.2.1, react ^19, tailwind ^4）
- **嵌入**：Workers AI `@cf/baai/bge-m3`（1024 维，多语言/中文友好），分批调用（8 chunk/批）
- **向量库**：Vectorize（Free 5M 维度 ≈ 4.8k chunks；`wrangler vectorize create kb-ask --dimensions 1024 --metric cosine` 一次性建）
- **生成**：magpie 中转（复用产品② `streamLLM` + 错误收敛），SSE 流式（step/token/done/error 协议同产品②）
- **持久化**：D1（documents + chunks 元数据 + qa_history），单库单索引（MVP）
- **检索**：向量 top-k=6 + 相似度阈值（基线 0.35，**用评测集扫曲线后写死**）；关键词兜底二期
- **鉴权**：独立副本 `checkAccessToken`（同产品② 口径），401 契约一致
- **部署**：`npm run deploy`（脚本内 `wrangler deploy --secrets-file` + 双探针）；部署后 `versions view` 必含 `AI`/`VEC`/`DB` 三绑定

### 模块边界（新建，不跨产品 import）
