# health-track 真实语料标定（字段级）

> 一句话：**4 份真实检验报告、32 行指标，行对齐/名称/结果/参考范围/状态全部 32/32，单位 28/32（87.5%）**；
> 第 5 份是腹部超声散文报告，被 `noMetrics` 明确拦下而不是硬凑指标。
>
> 复现：`cd product4 && ego-browser nodejs < e2e/live-corpus.mjs`

## 1. 为什么要有这份东西

在此之前，「真实语料可用」这个说法来自**我肉眼比对**和**数行数** —— 那是「看起来对」，不是数字。
合成语料（`npm run eval`）能证明**逻辑**对，但证明不了**可用性**：合成语料是我自己造的，
好走的输入我自己最擅长造。这份标定补的是后者。

## 2. 方法（口径先写清楚，避免自欺）

| 环节 | 做法 |
|---|---|
| 真值来源 | **逐份报告看图录入**（`eval/corpus/truth.json`），不是抄模型输出 |
| 真值字段 | 缩写 / 中文名 / 结果（含 `<`、`>`、界值符号）/ 单位 / 参考区间原文 / 报告上的方向标记 |
| 被测对象 | **线上** `https://health-track.ilikesaury.workers.dev` 的完整链路：PDF → 本地 PaddleOCR → 表格重建 → LLM 抽取 → 预览 |
| 停止点 | 每份都停在**确认闸**（不点「确认入库」，最后点「放弃」）——真实体检数据是否入库由人决定 |
| 比对 | `e2e/corpus-score.mjs`（纯函数）：位置优先配对 + 名称/缩写二次匹配；逐字段命中计数 |
| 单位口径 | **大小写不敏感**（`IU/mL` 与 `IU/ml` 同一单位，不扣分） |
| 状态口径 | 真值有 ↑ → 期望「偏高」，↓ → 期望「偏低」，无标记 → 「正常」或「无法判定」都算对（界值行判不出方向是允许的） |

### 单位缺失的 4 行（全部明细，不藏）

| 指标 | 真值单位 | 得到 | 原因 |
|---|---|---|---|
| `NEU#` 中性粒细胞数 | `10^9/L` | （空） | PP-OCR 把上标整段丢了（识别成 `10^/L`），还原不出 9 还是 12 → 判「单位未知」 |
| `LYM#` 淋巴细胞数 | `10^9/L` | （空） | 同上（识别成 `10/L`） |
| `EOS#` 嗜酸性细胞数 | `10^9/L` | （空） | 同上 |
| `PDW` 血小板体积分布宽度 | `%` | （空） | OCR 漏了这个 `%` 字符 |

**为什么置空而不是猜成 `10^9/L`**：同一份报告里另有 `WBC`、`MONO#`、`BASO#` 识别正确（`10^9/L`），
看起来可以「按同列多数推定」—— 但那是**猜测**。假单位会在跨报告比较时触发错误的
「单位变了」告警，比「单位未知」更糟。宁可显示未知，让人一眼看到缺什么。

## 5. 失败样例（这一节比成功更重要）

| 样例 | 现象 | 当前处置 |
|---|---|---|
| 腹部超声报告（散文式） | 模型**曾抽出 25 条**「指标」（正文里的尺寸/直径）；另一次返回空串 | 空串 → `noMetrics`/422「请改用手工录入」；抽出 25 条时 → 一条参考范围都没有 → **默认零勾选** + 提示「可能是超声/影像类报告」 |
| 血常规页脚碎行 | 「检验者 \| 打印者：李美娴 \| 审核者：…」落进指标行，重建出第 25 行 | `isMetricRow` 拒绝「名称或值里含 `键：值`」 → 24 行 |
| 乙肝五项里的同指标两行 | `HBsAg(H) 78.44` 与 `HBsAg 78.440` 是同一分析物的两种方法 | 预览保留两行、默认都勾；入库时按标准名去重（`dedupeByName`），不会变成两条趋势 |

## 6. 已知局限（不要拿这份数字说过头话）

1. **n = 32 行、4 份报告、同一家医院、同一批次、单页、150 DPI 导出** —— 数字只能说明
   「这条链路在这类扫描件上可用」，不能说明「所有医院报告都可用」。
2. **未验证的输入形态**：跨页表格、合并单元格、彩色底纹、竖排、手机拍照（倾斜/阴影/反光/印章）。
3. **单轮标定**：只跑了几轮，没有做多轮重复取方差（合成语料那套是 6 次重复）。
4. 单位缺 4 行是**真缺陷**（OCR 上标丢失），不是打分器问题；记为已知限制而非已修。
5. 这份标定**不覆盖**解读环节（红线守卫另有 `eval/cases/redline.cases.json`）与趋势聚合。

## 7. 两套评测的分工（别混）

| 套件 | 语料 | 证明什么 | 命令 |
|---|---|---|---|
| `eval/run.ts` | 6 份**合成**报告（28 行） | 抽取**逻辑**：箭头/中文日期/`≤`上限/定性值/`<0.01`/英文缩写 | `npm run eval`（需 `.secrets.json`） |
| `e2e/live-corpus.mjs` + `eval/corpus/truth.json` | 4 份**真实**报告（32 行） | **可用性**：真实扫描件能否被正确转录 | `ego-browser nodejs < e2e/live-corpus.mjs` |

两套都要绿：合成语料保证改代码不回归，真实语料保证不是「只在我造的输入上对」。
