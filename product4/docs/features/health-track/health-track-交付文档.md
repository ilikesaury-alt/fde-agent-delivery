## 1. 功能概述

把体检报告变成**可追踪、可核对、不越界**的健康数据：

| 能力 | 说明 |
|---|---|
| 报告导入 | 电子版 PDF（有文字层）自动抽文本；扫描件/图片型 PDF 走 OCR；也可直接粘贴文本 |
| 结构化抽取 | 报告文本 → 逐条指标（名称 / 结果 / 单位 / 参考范围 / 原文片段） |
| **人工确认闸** | 抽取结果先给**预览**，逐行核对原文片段并勾选，确认后才入库。不确认不写库 |
| 异常标记 | 对照**当次报告自己**的参考范围判偏高/偏低；解析不出范围则显示「无法判断」，不猜 |
| 趋势图 | 同一指标跨多次检测的折线 + 绿色参考范围带；参考范围跨次变化会显式提示 |
| AI 解读 | 解释指标含义、描述趋势（引用本人历史数据，可逐条核对）、给复查方向；依据不足拒答 |
| 手工补录 | 补录漏掉或纸质记录的指标，按检测日期归并 |
| 隐私 | 数据只存在本产品自己的 Cloudflare D1 里，无第三方分析/上报；令牌保护 |

**本版本不包含**（有意不做，不是缺陷）：
- 多成员档案 UI（表已预留 `profile_id`，本期只用单一 `default`）
- 诊断、用药建议、危急值报警（**产品红线，永久不做**）
- 手动合并指标名（跨医院同义变体只能分线显示）
- 图表缩放 / 多指标叠加 / 导出
- 定时自动巡检或提醒推送
- 针对特定医院报告模板的适配规则

## 2. 使用说明

### 2.1 访问令牌（右上角）
线上配置了 `ACCESS_TOKEN`。首次打开页面在右上角输入框填入令牌（记在浏览器本地），
否则所有接口返回 401（页面顶部会提示「访问令牌缺失或错误」）。

> 令牌值在部署机的 `product4/.secrets.json` 里（该文件不入库）。运维请用密码管理器保管。

### 2.2 导入报告
1. 选「电子版 PDF」上传 → 自动抽出文本，填入下方文本框；
2. 若提示「没有文字层」，改用「扫描件」上传同一文件 → 逐页 OCR（≤5 页），
   识别的文本回填到文本框，**必须逐行校对**（视觉模型会认错字，实测把「审核者」认成「电子书」）；
3. 也可以直接粘贴报告文本。

### 2.3 解析 → 确认入库（本产品的核心闸门）
点「解析指标」→ 出现预览表格，每行显示：指标名（及归一后的标准名）、结果、参考范围、状态、**原文片段**。
- 默认全选；把模型抄错的行取消勾选即可；
- 表格上方显示「已勾选 N/M · 异常 K 项」；
- 点「确认入库（N 项）」才写库；点「放弃」什么都不写。

**入库前请务必对照原文片段**：这是本产品防「错误数据进入健康档案」的唯一人工关口。

### 2.4 时间线 / 趋势 / 解读
- **时间线**：按检测日期倒序列出报告；点一项看明细（含报告原文）。
- **趋势**：选一个指标看折线图 + 参考范围带 + 逐次数据表；「参考范围跨次变化」会标黄。
- **指标解读**：选指标 → 点「解读该指标」。只解释含义与趋势，**不做诊断、不推荐药物**；
  没有数据时会明确拒答。

### 2.5 手工补录
填检测日期（默认今天）+ 指标名/结果/单位/参考范围。同一天的多次补录会合并为一份手工报告，
因此趋势与从报告导入的数据是同构的。

## 3. 权限 / 配置变更

| 变量 | 必填 | 说明 |
|---|---|---|
| `MAGPIE_BASE_URL` | ✅ | 上游 LLM 网关（OpenAI 兼容） |
| `MAGPIE_API_KEY` | ✅ | 上游密钥 |
| `MAGPIE_MODEL` | — | 默认 `deepseek-chat` |
| `ACCESS_TOKEN` | ⬜ 但线上必须设 | 设置后所有 `/api/*` 需 `Authorization: Bearer <token>` |
| `OCR_MODEL` | — | 覆盖视觉模型（默认 `@cf/meta/llama-3.2-11b-vision-instruct`） |
| `MAX_REPORT_CHARS` | — | 单份报告文本上限（默认 60000，超限直接拒绝而不是截断） |
| `EXTRACT_RETRY` | — | 抽取校验失败的重试次数（默认 1） |

绑定：`DB`（D1 `health-track-db`）、`AI`（Workers AI，仅扫描件 OCR 用）、`ASSETS`。
**无 Vectorize** —— 解读的数据全在 D1 行里，不做语义检索。

## 5. 已知问题与注意事项

1. **OCR 质量未经大规模验证**：仅用合成扫描件验证了链路可用（10/10）与关键数字可读；
   真实手机拍照（倾斜、阴影、印章）的表现**未验证**。因此 OCR 文本一律回填到可编辑框，
   强制人工校对，不自动入库。
1b. **抽取存在偶发漏行**：同一批 6 份自造报告重复评测 6 次，5 次行级 100%，**1 次漏了一行**
   （定性指标「尿潜血」）。因此「100%」应理解为「多数次全对」。**漏行只能靠确认闸兜底** ——
   这也是「抽取结果不自动入库」的另一条理由：预览里少一行，人能看出来；自动入库就永远不知道。
2. **抽取准确率来自自造语料**：行级 100%（28/28）是在 6 份自造报告上取得的；
   真实体检报告格式更多样（跨页表格、脚注、合并单元格），**真实语料标定未做**（需真实数据，暂不入库）。
   这是本产品最大的未验证面，落地使用时应先导入自己 3–5 份真实报告抽查。
3. **指标名归一字典只有 23 个高频指标**，且刻意**拒绝宽别名**：`血糖/glu/葡萄糖` 这类写法
   同时也是餐后血糖、OGTT、尿糖的写法，与空腹血糖**单位相同**，错并不会被「单位变化」告警拦下 ——
   所以宁可让它们各自成线。同理「尿素」不并入「尿素氮」（标度差约 2.14 倍）。
   未命中的指标按原文名（轻度清洗）聚合，界面会列出该序列的多个原文名，但不提供手动合并入口。
   带**性别分区**（`130-175（男）/115-150（女）`）或**数量级**（`0-10^9/L`）的参考范围一律不解析
   → 显示「无法判断」（这是有意为之，见上一条）。
4. **参考范围「宁缺毋滥」的代价**：`ref_text` 格式罕见（如「阴性」「0～10^9/L」以外的复杂写法）
   会解析失败 → 状态显示「无法判断」。这是有意的：宁可显示「无法判断」，也不给错误的异常结论。
5. **不做诊断/用药/危急值**：这是产品红线，不是能力不足。任何绕过（如把问题改写成非医疗措辞）
   也只能得到科普性说明 —— 模型侧还有第二道红线提示词。
6. **单人单档案**：表结构预留 `profile_id`，本期无多成员 UI。
7. **截图证据缺失**：本交付环境的浏览器截图接口对外站也超时（环境限制），
   UI 验证以 DOM 级断言（26 项）为准。

## 6. 部署与回滚要点（运维向）

### 部署
```bash
cd product4
node scripts/deploy.mjs           # 迁移 → 构建 → deploy --secrets-file → 双探针
node scripts/deploy.mjs --skip-migrate   # 无表结构变更时
```
- 首次需先建资源：`npx wrangler d1 create health-track-db`（已建，id 写入 `void.config.ts`）。
- **必须带 `--secrets-file`**，否则重部署会清空线上 secrets。
- 迁移只走 `wrangler d1 migrations apply`（本脚本已内含），不要用 `d1 execute --file`（不写台账）。

### 部署后必查（三个绑定，缺一不可）
```bash
npx wrangler versions view <version-id>   # 需同时含 env.ASSETS / env.DB / env.AI
curl https://health-track.ilikesaury.workers.dev/api/health
curl https://health-track.ilikesaury.workers.dev/api/reports -H "authorization: Bearer <token>"
```
注意：**沙箱环境 Node/curl 到 workers.dev 会超时**，这不是服务故障 —— 用浏览器通道验证。

### 回滚
```bash
npx wrangler rollback <version-id>   # 回滚到上一个已知可用版本
```
数据表结构变更的回滚：本产品只有 `0001`，无破坏性迁移；删表会丢数据，**不要**在没有备份时回滚迁移。

### 访问令牌轮换
1. 在 `product4/.secrets.json` 改 `ACCESS_TOKEN`；
2. `node scripts/deploy.mjs --skip-migrate`（脚本会用该文件重新写入 secrets）；
3. 通知使用者更新浏览器里保存的令牌（页面会以 401 提示）。
