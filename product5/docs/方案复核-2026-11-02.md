## 复核方法

不复用先前调研结论，直接查一手证据：Cloudflare 官方 Limits 文档、x-cli 官方文档（Tier 说明）、XActions 官方 troubleshooting（X 接口分层）、nitter / gallery-dl 的真实 issue、FxTwitter/FxEmbed 官方 API 文档。

## ⛔ 阻塞级发现（BLOCKING）

### B1 —— 「自动扫描热门」必须登录态，Spec A1 不成立

**证据（三类独立来源一致）**
1. **XActions 官方 troubleshooting**（`xactions.app/docs/guides/troubleshooting`）明确给出 X 接口分层表：
   - **Guest 层（无需登录）**：profiles、public user timelines
   - **Session 层（必须登录）**：**search**、followers、following、likes、bookmarks、DMs、**home timeline**
   - 未登录请求 Session 层端点，X 返回**裸 404**（看起来像"端点不存在"，实际是权限拒绝）。
2. **x-cli 官方文档**（`x-cli.tamnd.com/getting-started/introduction/`）：Tier 1 guest GraphQL「**实测 2026-07-28 只剩 5 个操作**（profile by handle/id、deeper timeline walk、tweet read、audio Space），**X 拒绝其在 GraphQL surface 上的其它一切**」。Tier 2（search / home timeline / bookmarks）**必须用自己浏览器的 session cookie**（`auth_token` + `ct0`，仅 auth_token 不够）。
3. 我们自己的 `xclaw.info` 采样：它展示「X 中文区每日数据」= 热门推文聚合，**这类站基本都带 session 或自建池**，不能作为「零登录可搜索」的证据。

**推翻的结论**：CONTEXT A1「Worker 用 X 免费 API 拉到**热门**推文」在**零登录**前提下**不成立**。免费接口的 guest 层只能拿「单帖 / 用户公开时间线」，**拿不到搜索、热门、trending、home**。

**影响**：Spec 的核心场景（自动扫描热门）与「零登录」两条约束**互斥**。必须三选一：① 引入 session cookie（零成本、但要登录态维护 + 风控）② 换第三方免费 hosted API（见 B3 的解法）③ 降级为「扫描指定账号的公开时间线」（无需登录，但不再是"热门"）。

### B2 —— Cloudflare Free 的 Cron CPU 只有 10ms，一次跑完整链极可能超限

**证据（官方 Limits 文档，2026-10-29 版）**

| 限额 | Workers Free | Workers Paid |
|---|---|---|
| CPU time per HTTP request | **10 ms** | 5 min |
| **CPU time per Cron Trigger** | **10 ms** | 30 s（<1h 间隔）/ 15 min（≥1h） |
| Subrequests per invocation | **50** | 10,000 |
| Cron Triggers per account | 5 | 250 |
| Duration（Cron） | 15 min（各套餐同） | 15 min |

**关键点**：网络上常见的「免费版能跑 15 分钟」是 **duration（墙钟）**，不代表 CPU 额度。**真正的瓶颈是 10ms CPU**——「等 fetch / 等 LLM」不计 CPU，但 **JSON 解析、评分组装、日报拼接、D1 读写编排**都计。

**推算**：一次 Cron 若做「抓 30 条 → 解析 → 本地预筛 → 组装评分请求 → 写 D1」，JSON 解析 + 对象构造 + 序列化很容易吃掉 10ms；再叠加 **50 个 subrequest 上限**（抓取 + LLM 调用 + D1 写入都算 subrequest），一次 Cron 装不下「抓取 + 全部评分 + 生成日报」三件事。

**推翻的结论**：CONTEXT A4「Cron 定时把精选聚合为日报」按当前"一次跑完"的设计，**在 Free 套餐下不可行**（除非实测量级远低于估算）。必须改成**小批量 + 多次调用**，或承认需要 Workers Paid（$5/月，与"零成本"冲突）。

**附**：「isolate 有少量弹性余量」是官方原话，但**不构成设计依据**——不能把方案建在超限豁免上。

### B3 —— 直连 api.x.com 被 Cloudflare 拦是**已有实证的常见故障**，不是理论风险

**证据**
- `nitter` issue #1236（2025-03-31）标题即：「profile pages no longer work **potentially due to cloudflare protecting api.x.com**」，日志为 `api.x.com | 524: A timeout occurred`，讨论中直接怀疑「服务器 IP 被封」。
- `gallery-dl` issue #5665（2025）：「**Guest tokens seemingly no longer work** with python-requests」——即"非浏览器指纹客户端拿 guest token 失败"。
- x-cli 文档自述必须发 `x-client-transaction-id` + 浏览器保真身份头，才能「不像 bot、不被限流」；XActions 文档说 guest token 激活失败会**返回 404 而非 401**（伪装成端点不存在）。
- Cloudflare Worker 的出口 IP 就是数据中心 IP，与上述被拦场景同构。

**影响**：增量 1 的 M0 若按"Worker 直连 api.x.com 拿 guest token + GraphQL"设计，**失败概率显著**，且失败信息会伪装成 404，排查成本高。

**可行的替代解法（复核带来的一手新证据）**：
`api.fxtwitter.com`（FxEmbed / FxTwitter 项目）——
- **免费、无需 API key、官方声明"目前没有严格速率限制"**（但保留封 IP/UA 的权利，要求标识 UA）。
- 端点覆盖：posts、threads、conversations、profiles、**search、trends、typeahead**（官方 API 文档见 FxEmbed 仓库，外部路径不属于本仓），基址 `https://api.fxtwitter.com`，`/2/` 前缀。
- 它**本身就是 Cloudflare Worker**（FxEmbed 自述 "FxEmbed is a Cloudflare Worker"），因此它天然解决了"数据中心 IP 被 X 拦"的问题——**由它去扛 X 的风控**。
- 返回体含 `likes` / `retweets` / `replies` / `views` / `author` / `quote` → **正好够我们的评分维度**。

## 给 Spec 的最小改动建议（3 条）

1. **A1 重写**：「Worker 通过**免费 hosted X 数据 API**（`api.fxtwitter.com`，无需 key）拉到**热门/搜索**推文列表」，直连 X GraphQL 作为 fallback（可选，需 session cookie），并把「零登录」从"已验证"降级为"待 M0 验证"。
2. **A4 重写**：Cron 拆成**多个小任务**（抓取 / 评分 / 日报各一次 Cron，或按 item 分页），每条预算受 **CPU 10ms / subrequest 50** 约束；新增 **A9**：单次 Cron 在 Free 套餐下不超 CPU/subrequest（附实测计数）。
3. **D2/D3 修订**：主源 = fxtwitter（免费 hosted），并登记"第三方依赖存活"为已知风险 + fallback 策略；「零成本 × 零登录 × Worker 纯内」三者不能同时成立时，**明确取舍顺序**。

## 附录二：更正——「页面免费」不等于「服务免费」，且存在第三种零成本路径

> 用户指出：`xclaw.info/zh/tweets` 打开就能看，没有收费。这个观察正确，我上一版表述过于简略，需更正。

**更正 1：免费的是「人看网页」，付费的是「机器取数据」**
- 推特页是**免费获客入口**（SEO/引流），抓取成本由站方承担——freemium 的常见形态。
- 同一域下的 `apidashboard.xclaw.info`（需登录领 Key）说明他们把**同一份数据**做成了**需鉴权的 API 对外供应**。
- 定价页（`xclaw.team/pricing`：Free 50 credits/月、Pro $20/月、Pro+ $60/月）展示的是**同名 Agent 产品**的订阅；是否与 xclaw.info 同一法人**未验证**，不应作为强断言。
- **对方案的结论不变**：无论他们收不收费，"我们能零成本复现"取决于**我们**有什么，而不是他们页面是否免费。

**更正 2：我漏了一条零成本路径（F）——直接读他们的公开页面**
- 实测 `https://xclaw.info/robots.txt`：`User-agent: *` / `Allow: /`；Content-Signal 为 **`search=yes, ai-train=no, use=reference`** —— 即**参考性使用（reference）未被禁止**，AI 训练被禁止。
- 技术上可行：其推文数据已 SSR 内嵌在 HTML（`self.__next_f.push`），Worker 可取页面并解析。
- 风险：① 依赖别家前端结构（改版即断）② 商业站可随时按 UA/IP 封禁 ③ **无 API 契约**（不是"欢迎你调"的接口）④ 与调 fxtwitter 的**公开 API**（明确对外、仅要求标识 UA）相比，体面程度与可持续性都更差。

**更新后的零成本三选（正式登记）**

| 代号 | 路径 | 自动扫描热门 | 我方成本 | 主要风险 | 体面度 |
|---|---|---|---|---|---|
| F | 读 xclaw.info 公开页面（SSR JSON） | ✅（现成热门+热度分） | 0 | 前端结构变 / 被封 / 无契约 | 低（爬商业产品前端） |
| G | `api.fxtwitter.com` 公开 API | ✅（search/trends） | 0 | 第三方存活 | 高（对方明确开放） |
| H | 自带 X session cookie 直连 GraphQL | ✅ | 0 | 养账号 / 封号 / cookie 过期 | 中 |

**架构建议（消化风险）**：`lib/xapi` 定义为**数据源适配器接口**（`fetchHot({q, window}) => Item[]`），实现 G 为主、F 为备、H 可选。换源只改一个文件，评估与交付证据不变。这个抽象只加一个接口、不加复杂度（奥卡姆可接受）。

## 附录三：G（api.fxtwitter.com）**M0 实测结果——不满足「自动扫描热门帖子」**

> 用户拍板数据源 = G。定稿前按纪律先做 M0 实测（不凭文档）。结果：**G 只能查单帖 + 列趋势词，不能搜帖子**。

**实测矩阵（2026-11-02，逐条真实调用）**

| 端点 | 结果 | 返回内容 | 说明 |
|---|---|---|---|
| `GET /jack/status/20` | ✅ 200 | 完整 JSON：`text` / `likes` / `retweets` / `quotes` / `bookmarks` / `author.followers` / `created_timestamp` | **单帖详情可用**，字段足够评分 |
| `GET /2/trends` | ✅ 200 | `trends: [{name:"Tanner McKee", context:"Sports · Trending"}, ...]` | **只给趋势关键词**，**不含任何帖子** |
| `GET /2/search?q=AI` | ❌ 404 | `{"code":404,"results":[],"cursor":{"top":null,"bottom":null}}` | **搜索不可用**（与 X guest 层同因：search 属 session 层） |
| `GET /2/search?q=AI&feed=top` | ❌ 404 | 同上 | 换排序参数无效 |
| `GET /2/search?query=AI` | ❌ 400 | `q: Invalid input: expected string, received undefined` | 证明**参数名 `q` 是对的**，即端点存在但服务端返回空 |
| `GET /2/nasa/timeline` | ❌ 404 | `Not found` | **无时间线端点** |
| `GET /2/nasa/statuses` | ❌ 404 | `Not found` | 同上 |

**结论**：G **无法把「趋势关键词」变成「帖子流」**（缺 search），也**没有账号时间线**端点。因此 G 单独**做不到**「自动扫描热门帖子」这个不可变定位。

**G 的真实能力**：单帖详情（✅ 强）、趋势关键词（✅）、搜索/时间线（❌）。适合做「**已知帖子的补全/翻译/校验源**」，不适合做主扫描源。

**因此零成本可选组合收敛为**

| 方案 | 热门帖子流 | 零成本 | 风险 |
|---|---|---|---|
| **F 为主**（读 xclaw.info 页面） | ✅ 现成（含热度分/排名） | ✅ | 前端改版即断 / 被 UA 封禁 / 无 API 契约 |
| **F 为主 + G 补全** | ✅ | ✅ | 同上（G 只补字段/翻译） |
| **H 为主**（X session cookie） | ✅ 完全自主 | ✅（cookie 免费） | 养账号 / 封号 / cookie 过期 |
| **G 单独** | ❌ **做不到** | — | — |

**建议**：**F 为主 + G 补全**（F 提供热门流，G 负责单帖详情/翻译/交叉校验）；若用户不愿依赖 F，则只能上 H（自带 cookie）。
