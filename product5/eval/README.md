# 评测集与阈值标定（产品⑤ 增量 3）

> 目的：让「精选」从**拍脑袋 top-N** 变成**可报数的筛选**。
> 方法平移自产品③ 的 RAG 四指标标定（见 `product3/eval/`），但标的物不同：
> ③ 标的是「检索找到没」，⑤ 标的是「这条该不该进日报」。

## 1. 数据与标注

| 文件 | 内容 | 由谁产出 |
|---|---|---|
| `labels.json` | 50 条真实资讯 + `shouldPublish` 布尔标签 | **agent 初标，待用户复核**（见下） |
| `scores.json` | 同一批条目的真实模型评分快照（来自线上 `/api/top?threshold=0`） | 线上 Worker 实跑（真 magpie） |

**标注口径**（回答「这条该不该进我今天的 AI 资讯日报」）：

- `true`：与 AI/前沿技术相关，且对读者有信息增量（新发布、新论文、新工具、有价值的深度分析）
- `false`：与 AI 无关（纯消费电子/体育/财经）、纯观点情绪、重复报道、标题党、招聘/广告

**诚实声明**：这 50 条标签由 agent 依据标题+摘要判定，**不是人工标注**。
它的作用是**让标定流程跑通并给出可复核的数字**，而不是宣称「已人工标定」。
用户复核方式：直接改 `labels.json` 里的 `shouldPublish` 后重跑 `npm run eval`，
报告会随之更新（口径变了要改 `note` 并注明复核人）。

## 2. 指标口径

| 指标 | 定义 | 为什么重要 |
|---|---|---|
| **Precision** | 入选里真正该进的比例 | 日报里塞垃圾，用户就不看了 |
| **Recall** | 该进的里面被选中的比例 | 漏掉重要新闻，雷达就失去意义 |
| **漏选率** | `1 - Recall` | 直接对着交代：今天漏了几条 |
| F1 | Precision/Recall 调和均值 | 选阈值的单一参照 |

**取舍倾向**：本产品宁可**牺牲一点 Precision 保 Recall**——
漏掉一条重要发布，比日报里多一条无关资讯更伤（资讯可以快速滑过，漏了就不知道）。

## 3. 标定流程

```bash
# 1) 从线上拉真实评分快照（有网环境；本机需带代理）
curl -sS --proxy http://127.0.0.1:7890 \
  "https://ai-hot-radar.ilikesaury.workers.dev/api/top?threshold=0&limit=60" > eval/scores.json

# 2) 按标签跑阈值扫描（纯本地，不触网）
npm run eval
```

`eval/run.ts` 会扫 `threshold ∈ {50,55,60,65,70,75,80}`，输出每个阈值的
Precision/Recall/F1/漏选率，并给出推荐阈值（F1 最高；并列时取 Recall 更高者）。
