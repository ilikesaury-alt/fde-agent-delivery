# 作品集总览 · FDE 交付能力实证

> 面向评审 / 面试 / 客户的一页入口：我如何把「一个模糊需求」交付成「已上线、有验收证据、可交接、可维护」的产品。
> 目录索引见 [README](../README.md)；单产品细节见各产品工作原理 / 交付文档。

## 1. 一句话

两年多的个人 FDE 实践沉淀为一套可复用的交付流水线（`dev-task-flow` 11 步），并用它从零交付了 **三个已上线产品**——每个产品都留下「需求活文档 + 原理文档 + 交付文档 + 真实 E2E 证据 + 部署记录」的完整闭环，同时把每次踩到的平台级坑沉淀成可复用的 Skill（现 4 个通用技能）。

第三个产品（RAG 知识库问答）上线时暴露了一个更值钱的事实：**本地全绿、绑定齐全、探针正常，功能依然可以全坏**。缺陷只在真运行时显形，完整排障现场见 [deploy-kb-ask.md §5](../product3/docs/deploy-kb-ask.md)。

产品③ 的二期（多轮会话 / 会话侧栏 / 混合检索 / 扫描件 OCR / 索引延迟提示）把这个教训推到极致：**上线后我又逐条做了线上人工验证**，结果又抓出 7 个只有真环境才暴露的缺陷（视觉模型返回空对象、许可 5016、锚点链稀释导致误拒、D1 变量上限、迁移台账、向量异步延迟、OCR 鉴权文案混淆），全部当场修复并复验 —— 这一轮的完整清单见 [CONTEXT §15](../product3/CONTEXT.md)。

## 4. 交付方法论：9 步流水线

`dev-task-flow`（详见产品 CONTEXT 的「流程状态」章节，三产品均逐步留痕）：

```
① 准备        初始化 CONTEXT.md（需求活文档，全程只增不改口径）
② 需求对齐    多轮收敛 → 验收标准写死，四层（目标/边界/输入/输出）无未决歧义
③ 方案设计    第一性原理 + 对抗性审查 + 奥卡姆；现状标注（哪些复用、哪些新建）
④ 实现        M0 先打穿最小闭环（技术风险最高的一条链路），再铺业务
⑤ 交叉对抗审查 子 Agent 多方向审查（产品②：15 项 → 4 阻塞 + 11 非阻塞；产品③ 二期：12 条发现逐条处置）
⑥ 人工 Review 验收标准逐条对账 + 业务路径走查 + 二次奥卡姆（删临时探针）
⑦ 交付文档    面向测试/业务方（不含实现细节）
⑧ 提交        标 E2E pending / done，证据入 docs
⑨ HANDOFF     面向下一个开发会话（现状 + 坑 + 下一步）
⑩ 复盘        重复流程沉淀成 Skill；本工作流自身的漏项回补
⑪ 端到端自测  部署 + 核验 + 接口级 E2E + 浏览器人工用例（本次由 agent 在真环境代跑）
```

关键的三个反直觉结论（都在三个产品上被验证过）：
- **M0 打穿优先**：三产品都是先做「最高技术风险链路」的最小验证（产品① 先验 magpie 连通，产品② 先验 SSE 端到端，产品③ 先验 Vectorize/Workers AI 绑定透传），失败就回第 3 步改方案，而不是先铺 UI 再发现路走不通。
- **文档是交付物，不是副产品**：文档口径（commit/version/证据）必须能被下一个人直接核对，过期即视为缺陷。
- **坑必须写「根因 + 探测器」**：只写「别这么做」没有价值，要写「怎么 30 秒内判断是不是这个坑」。

## 6. 踩坑沉淀（平台级经验 → 可复用资产）

| 事故 / 坑 | 根因 | 沉淀形态 |
|---|---|---|
| 线上 1101（全站 500） | 部署时跳过静态资产上传，版本绑定里缺 `ASSETS` | 部署铁律：部署后必查 `versions view` 资产绑定 + `assetUploadFileCount > 0`；已固化进 `deploy.mjs` 探针 |
| focus-hang（聚焦后 15–31s 卡死） | `pages/layout.tsx` 返回 `<html>/<head>/<body>` 导致 SSR 水合错位 | 完整复盘 [ROOT-CAUSE-FINAL](../product1/docs/e2e-evidence/focus-hang/ROOT-CAUSE-FINAL.md)；方法论沉淀为 `perf-hang-triage` Skill（先判定故障层，再选探针） |
| SSE 流式不关闭连接 | `void/sse` keepAlive 需手动 `stream.close()`；测试必须消费完响应流 | 写入产品② 工作原理文档 + 单测约束 |
| 沙箱内 workerd 不可 spawn | `vite dev`/miniflare 需子进程、`npm install` postinstall 需下载二进制 | 本地用 Node shim 验证（`product1/e2e/server.mjs`）；`npm ci` 走 `--ignore-scripts`；真启动验证挪进 CI |
| **Vectorize `upsert` 是异步的**（实测 50–90s 才可检索） | 平台契约：返回 mutationId 仅代表已入队 | 不能把导入阻塞在「等可见」上；mutationId 即验收凭据 + 记录 `indexed_at`；索引追上前属优雅降级；产品侧给「索引中 / 已就绪 / 可检索」三级徽标 + 探针接口 |
| **用 `getByIds` 做回读校验造成孤儿向量** | upsert 后数十秒读不到 → 假阴性 → 补偿删 D1 行 → 向量永留索引 | 回读失败**绝不**做破坏性补偿；异常路径只标 failed 并保留数据 |
| **Vectorize `query` 拒收布尔 false** | runtime 绑定解析 `returnMetadata: false` 报 40026 | 只传 `{ topK }`；本地替身不认这些选项测不到 → 必须有线上 E2E |
| **D1 单条 SQL 绑定变量上限 100** | 平台限制（本地 SQLite 是 32766 → **本地测不出来**） | 多值语句按**变量数**切批（不是行数）；常量固化进代码，避免线上 502 |
| **`d1 execute --file` 不进迁移台账** | 绕过 `migrations apply` → 下次 apply 重复执行 → `duplicate column name` | 迁移一律走 `migrations apply`（在 `dist/ssr/` 下跑） |
| **Workers AI 视觉模型对所有入参返回 `{}`** | 模型端不可用，HTTP 200 但无内容（静默失败） | 换模型族 + 保留旧形状适配可切回；**目录标了能力 ≠ 现在能用**，必须真环境实测一张图 |
| **Workers AI 首次使用需同意许可（5016）** | 许可动作的入参形状随模型族而变，用错形状 → 同意从未生效 | 识别 5016 → 自动提交同意（幂等）→ **只重试一次**；许可形状按模型族分别构造 |
| **多轮改写的锚点链稀释召回** | 改写把历史锚点逐轮累加 → 第三轮起真意图被稀释 → 误拒 | 双路检索：改写查询 + 原始问题各检索一次，RRF 跨列表合并 |
| **OCR 全失败但不提示缺令牌** | 鉴权失败与「识别失败」共用一条文案 → 排查方向完全跑偏 | 401 与识别失败**分两条提示**；错误分类映射不同 HTTP 码（400/429/502） |

## 9. 已知边界（诚实清单）

- **单用户定位**：产品② 用共享访问令牌保护，不是多租户；`sourceText` 落库全文，多人使用需重做权限与存储设计。
- **抓取成功率不可控**：Workers 无浏览器内核，动态渲染/登录墙页面抓不到正文——这是设计边界，粘贴文本是一级路径。
- **无集中监控告警**：依赖 Cloudflare 日志 + `wrangler tail` 人工排障，未接 APM/错误聚合。
- **模型延迟波动大**：同一 prompt 首 token 1.8–22.9s，个别模型 90s 无输出，已用步骤进度 + 空帧兜底缓解，但未做多模型自动降级。
- **工程债**：产品② URL 抓取无重试（换取快速失败）；DoH 校验与真实 fetch 之间仍有 DNS rebinding 的 TOCTOU 窗口（接口需令牌，风险已登记）。
- **产品③ 索引延迟**：Vectorize 写入异步，实测 50–90 秒才可检索；导入后立刻提问会收到「未找到依据」。已做文档徽标（索引中·约 N 秒 / 已就绪未验证 / 可检索已验证）+ 探针接口 + 拒答时提示「索引异步」。
- **产品③ 阈值已在真环境标定**（2026-10-28：线上 21 例 Recall 100% / 拒答 100% / 误拒 0% / 引用准确 100% → 0.45 无需调整）。但语料仅 4 篇，上量后需按评测脚本重扫曲线。
- **产品③ 无监控**：`wrangler tail` 在本机不可用（websocket 超时），线上排障依赖临时诊断端点 + D1 补偿记录，未常态化。
- **产品③ 无用户隔离**：单用户令牌模型，`ACCESS_TOKEN` 未配置即对公网开放（上线前必须配置）。
- **产品③ 已知风险（评审判定「记录」而非修复）**：OCR/探针的额度消耗可被重复调用放大（单用户令牌模型下未做配额计数）。
- **产品③ 共享上游隧道会突然失效**：症状是「生成类接口报服务不可用，其它正常」（`Unauthorized: Tunnel not found`）。换域名后需同步三处（两个 `.secrets.json` + 每个 Worker 的 secret + 重新部署）。已建议改用命名隧道（见 [线上环境速查](./线上环境速查.md) §4 R3）。
