## 3. 访问令牌

**存在哪**

| 产品 | 位置 |
|---|---|
| ① | 只有线上 Worker 里；本地无 `.secrets.json`。值登记在 `.access.local.md`（本地） |
| ②③④ | `product2/.secrets.json`、`product3/.secrets.json`、`product4/.secrets.json`（**均已 gitignore**；④ 用独立令牌 `ht_` 前缀） |

**怎么取**（不打印到终端记录里）

```bash
# ②③：从本地 secrets 文件读
node -e "console.log(require('./product3/.secrets.json').ACCESS_TOKEN)"

# 直接复制到剪贴板（推荐，值不进终端/日志）
node -e "require('child_process').spawnSync('cmd',['/c','clip'],{input:require('./product3/.secrets.json').ACCESS_TOKEN})"
```

**线上改令牌**（改完旧令牌立即失效，需重新在页面填入）

```bash
cd product3
echo "<新令牌>" | npx wrangler secret put ACCESS_TOKEN --name kb-ask
```

> ⚠️ 重部署若**不带 `--secrets-file`** 会清空全部 secrets（①②③ 都踩过）。部署脚本已强制携带。

## 4. 共享依赖：magpie 网关（单点，地址易变）

三个产品的 LLM 调用**都走同一个 magpie 网关**（OpenAI 兼容 `/chat/completions`），由本机 `cloudflared` 快速隧道对外暴露。

| 事实 | 影响 |
|---|---|
| 隧道是 **`*.trycloudflare.com` 快速隧道，每次重启域名就变** | 隧道一变，**三个产品的生成能力同时挂**，且必须逐个 `wrangler secret put MAGPIE_BASE_URL` 才能恢复 |
| 历史已换过至少 5 个域名 | `tahoe-mainland-…`（① 首版，已失效）→ `corporate-relationship-…` → `quantities-bulk-…` → `glenn-liabilities-collectibles-outline`（2026-10-28 10:10 被服务端回收）→ **`strange-healing-manuals-ada`（2026-10-28 18:35 重建，②③ 当前使用）** |
| **隧道被回收时的症状** | 线上 `/api/ask` 报「AI 服务暂不可用」而 `/api/documents` 正常 —— 生成链路挂、其它正常。查 `tools/tunnel.log` 里的 `Unauthorized: Tunnel not found` |
| 桥接跑在本机（`cloudflared` + 本地 `:3425`） | 本机关机 = 三产品都无法生成；静态页与 D1 只读仍可用 |
| 模型名 `auto/minimax-m3.1-flash` | 换模型需改三处 `MAGPIE_MODEL` |
| **① 的当前值与 ②③ 未必相同** | ① 的 secrets 无本地副本，实际值只能靠生成请求反推；本节**不登记 ① 的地址**，避免写错 |

> **不要在本文件把"当前隧道地址"当长期事实** —— 它随时会变。要拿真实值：②③ 读 `.secrets.json`；① 用一次生成请求实测（能出 6 板块即说明上游活着，2026-10-28 实测通过）。
>
> **换域名后必须三处同步**（2026-10-28 实测：漏一处 → 该产品生成能力静默挂掉）：
> ① ②③ 的 `.secrets.json` ② 每个 Worker 的 `wrangler secret put MAGPIE_BASE_URL` ③ 每个 Worker 重新部署（secret 变更要重新部署才生效）。
> product1 没有本地 `.secrets.json`，只能靠线上 secret 变更 + 生成请求反推。

**建议**：换成**命名隧道**（固定域名），可一次性消除前两条。未做，登记为 R3。
